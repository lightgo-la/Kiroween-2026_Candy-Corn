# Structure

```
src/
  main.rs              clap entry point: GUI / --blueprint / --cli / --mcp / --canvas / --run-graph, --lang (with Korean help), window icon
  i18n.rs              language (English/Korean): tr!/trf!/trp! macros, Tr constant pairs, global language + per-thread test override (with_lang), settings file (%APPDATA%\Candy-Corn\settings.json), source checks (no Hangul in Rust sources, unused translations)
  lexicon.rs           Korean linguistic constants generated by build.rs from locales/lexicon.ko*.json
  app.rs               GUI: 3-pane, workers (mpsc, generation numbers drop stale results), blueprint apply, LLM run, undo, samples menu, open reply
  keys.rs              🔑 API keys window: Credential Manager, custom endpoints in settings.json (base_urls), connection test, model pickers
  llm_view.rs          VIII visuals: field chips, token bars, run history, ReplyModel (parsed once on the worker) and the Analysis tab (tables, sort/filter, charts, coverage, CSV)
  blueprint.rs         blueprint (.kiro, v3: llm_options) format, coordinate cleanup, data path resolution, 5 built-in blueprints
  history.rs           debounced undo/redo history
  studio_canvas.rs     blueprint canvas (settings, data, role, constraints, output -> compiler -> result -> LLM)
  theme.rs             palettes of design samples 01-07, cards, glow buttons, fog, app icon
  pipeline.rs          compile pipeline shared by GUI/CLI/MCP, steering bullet parser (skips code fences), LLM reply check (check_reply), raw token cache, target comparison
  ast/mod.rs           RootPromptAst and sub-ASTs
  ast/linter.rs        visitor passes: fillers, duplicates, contradictions, schema
  ast/codegen.rs       Claude XML / GPT Markdown / Gemini sections
  profiler/csv_profiler.rs  CSV/JSON/NDJSON streaming stats, sampling, z-score outliers
  tokenizer.rs         token counts and cost
  mcp_server.rs        stdio JSON-RPC MCP server
  canvas/              separate graph tool (exec, graph, llm, mcp_client, ui). llm.rs is also used by the GUI LLM run
  qc.rs                QC randomized invariant tests, 13,000 cases: compile 6,000 + profiler 4,000 + LLM reply check 2,000 + English-mode compile 1,000 (test builds only)
locales/
  ko.json, ko.<area>.json   Korean UI text keyed by the English text (build.rs -> ko_text!)
  lexicon.ko*.json          Korean linguistic data (build.rs -> crate::lexicon)
tests/scenarios.rs     33 scenarios: prepare inputs -> run the executable -> check the output (part of cargo test; s30-s33 compare --lang ko with the English default)
tests/graph.rs         16 --run-graph end-to-end tests (input placeholder, trust gates, test_node, --lang, ...)
tests/qa.rs            QA 1,000 runs (--ignored) + blueprint CLI test
tests/samples.rs       5 tests: every sample profiled by the real exe, every sample blueprint compiles, sample bytes keep their encodings, MCP refuses non-data files
tests/fixtures/        ko.<area>.json: Korean test inputs (build.rs -> ko_fixture!)
assets/                icon.ico (exe), icon-256.png (window and header). Source: pumpkin_premium.png
samples/               synthetic data in 9 formats/encodings + sales.csv, 10 sample blueprints (.kiro), replies/ (sample LLM replies), flow.canvas.json (graph for --canvas); README.md lists the planted problems
tools/gen-samples.ps1  regenerates the 9 generated sample files (fixed seed); the rest of samples/ is hand-written
build.rs               exe icon and version resource; generates ko_text!, the crate::lexicon constants and ko_fixture!
```

The app parses the `- ` bullets of `.kiro/steering/compiler-rules.md` directly as constraints. These files (product/tech/structure) are not parsed.
